## 3. Version-identifier validation: exact code paths

### 3.1 One identifier regex, no release-only check

`tools/version_port.py:62-65`:

```python
def safe_version(version):
    if not re.fullmatch(r"[A-Za-z0-9_.-]+", version) or version in {".", ".."}:
        raise ValueError(f"Unsafe version identifier: {version!r}")
    return version
```

`tools/lab.py:33-38`:

```python
def pinned_version():
    """The Minecraft version research-lock.json pins: every tool reads it from there, never by hand."""
    version = json.loads(LOCK.read_text(encoding="utf-8"))["minecraft"]["version"]
    if not re.fullmatch(r"[A-Za-z0-9_.-]+", version) or version in {".", ".."}:
        raise ValueError("Unsafe version identifier in lock file")
    return version
```

`26.4-snapshot-10` satisfies both. The regex exists as a **path-traversal guard** (it is used to build
filesystem paths and git refs), not as a release/allow-list check.

### 3.3 `diff` / `report` / `harnesses` / `regen` / worktrees — no gate

  ```python
  def port(args):
      """prepare both, diff, regen, report."""
      old = args.old or pinned()
      for version in (old, args.new):
          prepare(argparse.Namespace(version=version, download=False, jobs=args.jobs))
      diff(argparse.Namespace(old=old, new=args.new))
      if not args.no_regen:
          regen(argparse.Namespace(new=args.new, base=args.base, worktree=None, only=None))
  ```

### 4.3 Three traps that will otherwise corrupt the research (PASS, from code reading)

1. **`port`/`report` default `old` to `pinned()`.** Once `research-lock.json` is bumped to the snapshot,

3. **`report` calls `load(pinned(), "facts.json")`** (`version_port.py:626`). Keep the lock at 26.3 until
   26.3 has been prepared in the version store, or bump it first and prepare the snapshot — either way
   both versions need `facts.json` before reporting.

### 5.2 Network protocol — rank 1, highest manual effort (PASS for change list, NOT TESTED)

Official 26.4 network changes:
- **Modified Login Protocol**: encryption and compression are no longer applied implicitly. The server must
  explicitly send connection options in `minecraft:login_finished` (clientbound) or `minecraft:apply_options`,
  acknowledged by `minecraft:login_acknowledged` / `minecraft:options_applied`. Every subsequent packet uses
  the new settings.
- **`minecraft:intention` modified**: `host` may carry URI-style `key=value&…` properties, `_`-prefixed keys
  reserved; `<id>@<host>` parses to `host?_id=<id>`; SRV resolution adds `_o`; field length 1024.
- **`minecraft:transfer` modified**: new string-map `properties` field copied into the target's `intention`.
- **New `minecraft:mod_list` custom payload** sent empty by vanilla in configuration (Horizon's existing
  `horizon:mod_list` at `crates/horizon-protocol/src/mod_list.rs` is a *different*, Horizon-specific channel —
  keep it, don't conflate; the task also says to remove general mod support, so coordinate with Agent 7).
- **Entity position sync includes full-precision head rotation** (entity data/tracking).
- Server now disconnects clients more consistently on packet errors.
- Dedicated-server properties: `allowed-connection-ids`, `enable-legacy-status`, `key-rotation-period-seconds`,
  `status-contact-details`.

Fork files: `crates/horizon-protocol/src/{ids.rs,connection.rs,frame.rs,crypto.rs,entity_data.rs,packets/login.rs,packets/configuration.rs,packets/play.rs,packets/handshake.rs}`,
