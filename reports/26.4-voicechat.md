## 1. Executive summary

Simple Voice Chat is **not** a `.hmod`/Fabric mod in this fork. It is a first-class, compiled-in subsystem: a standalone Rust engine crate (`voicechat_engine`) plus a game-side glue module, a render-side menu module, an audio output tap, and four Android platform bridges (mic permission, audio-mode routing, hardware-volume sync, runtime feature flags). It was ported from Starling PR #310 in commits `65a66d6` → `8437d0c` and is intact on `dev/26.4`.

The protocol is **mod-versioned, not game-versioned**: the SVC wire format (compatibility version 20, `voicechat:*` plugin channels, AES-128-GCM UDP) is independent of the Minecraft 26.3→26.4 protocol. What *can* break in the migration is the **transport and context glue**: the CustomPayload packet definition, channel registration, own-player UUID, and entity/player position lookup. Those are all owned by Agents 1/3 (protocol) and 5 (Android platform), so voice-chat needs no version-constant edits of its own beyond verifying those seams.

**The single biggest risk is not the version bump — it is Agent 7 (mod-support removal).** Voice-chat registers itself through the fork's *native mod* API (`NativeMod` listing, `native_on`, `native_setting`/`native_set_setting`, `native_mod_key`, and the `native_mods`/`native_settings`/`native_settings_click`/`native_key`/`native_frame`/`native_tick`/`native_hud` dispatch hooks). If Agent 7 deletes that infrastructure as "mod support," voice chat loses its enable switch, its settings storage, its keybinds, its Options > Mods row, and its tick/HUD callbacks. **These native-mod hooks must be declared out of scope for removal (or voice-chat must be migrated off them).** See §5.

## 5. Cross-cutting constraint: native-mod infrastructure is load-bearing for voice chat

Voice chat is a *fixed, compiled-in* mod bundle (`android_bundled.rs` header: "Fixed MIT-licensed Android mod bundle. No downloaded code or phone compiler."), but it reuses the native-mod API for its lifecycle and persistence:

| Voice-chat need | Infrastructure it uses | Defined at |
|---|---|---|
| On/off switch | `native_on(ID)` → `settings.mods.disabled` | `game/native_hooks.rs:10573` |
| Keybind choice | `native_mod_key(ID, …)` → `settings.mods.keys` | `game/native_hooks.rs:11437` |
| Settings get/set | `native_setting` / `native_set_setting` → `horizon-mods/.horizon-mod-data/<id>/<key>` | `game/native_hooks.rs:11481-11489`; `native_data_dir` at 11470 |
| Options > Mods row/page/click | `NativeMod` (struct in `mod_api.rs:438`) + `native_mods/native_settings/native_settings_click` in `android_bundled.rs` | `game/native_hooks.rs:3175`, `android_bundled.rs:132-166` |
| Per-tick / per-frame / HUD / key dispatch | `native_tick`/`native_frame`/`native_hud`/`native_key` dispatchers | `game/native_hooks.rs:2247-2251, 2520-2523`; `android_bundled.rs:107,176` |

**Directive for Agent 7 and the coordinator:** general mod support = downloadable `.hmod` content/WASM mods, resolver, mod manager UI, Fabric/Quilt/Forge layers, mod JNI. The **native-mod helper API and the fixed Android bundle registry are NOT that** — they are the host interface voice chat and the other bundled extras (zoom, minimap, recipes, smart F3) run on. Removing them would delete voice chat's enable switch, keybinds, settings persistence, menu row, and tick/HUD callbacks. If the native-mod API is removed, voice chat must first be rewired to direct `Settings` fields / a dedicated options page (out of scope for this Agent-6 read-only pass; flag as an adaptation task). **Status: PRESENT, needs explicit protection in Phase 5.**

Also preserve the `settings.mods` fields (`disabled`, `keys`) in the settings type, or migrate voice-chat's `native_on`/`native_mod_key` calls.
