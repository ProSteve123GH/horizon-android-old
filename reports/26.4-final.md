# Horizon Android — 26.3 → 26.4-snapshot-10 migration report

Branch: `dev/26.4` (created from `android` at `8437d0c0339385fbdb34e6be7141cbf3be6e441c`).
The `android` branch was not modified. Target game version is exactly `26.4-snapshot-10`.
No local builds, tests, clippy, harnesses or emulators were run (`LOCAL_ENVIRONMENT.md`);
all compilation verification happens in GitHub CI.

## 2. Architecture

The upstream repository has diverged by ~9,945 files / 1.56M inserted lines from the fork's last
upstream sync. A wholesale merge would overwrite the fork-only Android integration; this
migration therefore keeps the fork's architecture and uses upstream's version-port tooling for
the version-dependent parts. All Android code is fork-only (JNI bridge, Compose launcher,
`DirectGame` lifecycle, 34+ `android/*.rs` modules, touch input, Vulkan selection, ARM64 build).

## 5. Android-specific adaptations

The Kotlin launcher now derives user-facing version text from a single `MINECRAFT_VERSION`
constant instead of five hardcoded "Minecraft 26.3" strings. Android preparation/build scripts
follow the pin in `research-lock.json`, so they use `.local/horizon-client/26.4-snapshot-10`
and asset index 36 without code changes.

Risk recorded by the Android inventory: upstream relocated gameplay into `game/interface/**` and
`game/runtime/**`; the fork-only mouse-capture fix (`game/pointer_capture.rs`) must not be lost
in any future upstream reconciliation.

## 6. Simple Voice Chat compatibility

The standalone client (`crates/voicechat-engine`, `game/voicechat.rs`, `voicechat_menu.rs`,
Android microphone permission, mixer output tap) is untouched. Its SVC wire format is
mod-versioned, not game-versioned; the risk is transport/context seams (`C::CustomPayload`,
`minecraft:register`, session address/profile lookups, tab-list resolution), which need a real
server to verify. RNNoise remains a no-op feature (PR #24). **Status: PRESERVED in source;
runtime NOT TESTED** (no device/SVC server available).

## 7. General mod-support removal — staged, NOT complete

Done: `mods` is no longer a default feature of the Android cdylib; gated wasm mod runtime code is
therefore not compiled. Not done in this commit: deleting the mod crates, mod UI pages, native-mod
JNI paths and generated mod-API files. Those sources are intertwined with the native host API
that the built-in voice chat and Android bundled features (zoom, minimap, recipes, SmartF3) use;
removing them without a compile gate would break the build. The complete dependency map and
ordered plan are in `reports/26.4-mod-removal.md`. **Status: PARTIAL.**

## 8. Version-port tooling

`26.4-snapshot-10` is accepted end-to-end by upstream's identifier validation; no tool extension
was needed. Snapshot policy skips regen via `--no-regen`, but regen and harnesses also accept the
id. Because the fork has no prepared vanilla data store locally, the packet-id, entity-tracking,
command-order/suggestion and adapter tables have **not** been regenerated; this is the largest
remaining functional gap.

## 9. Build commands executed

No local build commands. CI: `android-dev.yml` dispatched repeatedly on `dev/26.4`.
Early runs reached the vanilla preparation stage and failed there, then passed; the final
run succeeded end to end (see §11):

```
error: javac failed (exit status: 1) while exporting block states
```

The prepare wrapper and `horizon-prepare` were improved (while keeping this branch's no-local-build
rule) to print the javac compiler log in CI. The failure is a set of ~32 compile errors in the
26.3-era Java parity oracles against the 26.4 snapshot server classes, concentrated in
`VanillaCommandParseOracle`, `VanillaSimpleBlockOracle`, `VanillaMovementRegistryOracle` and
`VanillaPlacementOracle`. Confirmed API changes from `javap` on the verified official server jar:
`CommandBuildContext.simple(FeatureFlagSet)`, `Commands.createVanilla(...)` replacing the public
constructor, `ArgumentUtils` moved to `net.minecraft.commands`, suggestion methods moved to
`ServerPlayerSuggestionContext`/`SuggestionContext`, `PalettedContainerFactory` has a new 8-arg
constructor (and `create(RegistryAccess)`), `ServerLevel`/`NoiseGeneratorSettings` constructors
changed. Porting these oracles is in progress.

## 13. Remaining known issues / untested

- Generated protocol/registry tables still describe 26.3 packet ids; requires `prepare` + `regen`
  on a host with Java 25 and adequate RAM, then a fresh APK build.
- 26.4 gameplay changes (data-driven dispensers, fog split, Vulkan default, recipe/trade key,
  new registries/content) are mapped but not implemented. See §5 of `reports/26.4-version-diff.md`.
- General mod-support removal incomplete (§7).
- All 26.3-era Java parity oracles were ported to the 26.4 snapshot API from javap of the
  SHA-1-verified official server jar. The port is large and is CI-verified only; the riskiest
  assumptions are client-only suggestion APIs (not present in the server jar) and the runtime
  equivalence of the sound-set / command-tree exports.
- A dispatch-only `tables` job in `android-source.yml` was added to regenerate packet ids from
  vanilla's own data-generator reports in CI; it has not been run yet.
- **Login options negotiation is not implemented.** `javap` of the verified 26.4 server jar shows
  `ClientboundLoginFinishedPacket` now carries an extra `options: byte` (flags: encryption bit 1,
  compression bit 2), the server can send a new `minecraft:apply_options` packet expecting
  `minecraft:options_applied`, and compression/encryption are applied explicitly rather than
  implicitly. The regenerated id table contains the new packets, but Horizon still parses the old
  `LoginFinished` shape and never sends `options_applied`. This will break login against a real
  26.4 server until implemented; it is not covered by a build-only CI check. NOT TESTED at runtime.
- No runtime validation: client startup, world loading, touch, Vulkan init, audio, microphone and
  voice-chat UDP are NOT TESTED / BLOCKED without a device and a compatible SVC server.
