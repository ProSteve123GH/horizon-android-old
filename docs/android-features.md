# Android feature support (0.7.2 development)

Support varies by device and build architecture. The table lists implemented
integrations and remaining platform work; device-specific validation is described
in the [Android guide](android.md#check).

| Horizon feature | Android integration / remaining work |
|---|---|
| Controller action mapping | Touch uses the same actions, default Java eight-direction or optional analog movement, and toggle sneak. Hardware controller enumeration/stick input still needs a native Android backend; do not infer it from desktop gilrs support |
| Touch layouts | Four explicit schemes, normal Options > Controls settings, 16–64 px circle, optional 360-degree movement, sprint visibility, editable layouts, custom key buttons, global size and per-button scale/opacity sliders, handedness and direct F3/F5 buttons; passive HUD safe-area margins are in Accessibility. Launcher layout profiles snapshot an instance's arrangement (mode, placements, visibility, custom-key positions) for create/apply/rename/duplicate/delete and reset; applying never touches sensitivity/handedness/gyroscope or key actions |
| Contextual touch | Use action for held items/entities; movement actions serve flight/swimming. Not all Bedrock contextual icons/gestures are implemented |
| Controller vibration settings | Phone `Vibrator` now wired to existing game events and the existing vibration switch; no adaptive triggers or external-pad vibration backend |
| Physical keyboard / mouse | One stock NativeActivity with selectable input mode; normal keyboard, modifiers, cursor/buttons/wheel and relative pointer-capture path in Rust. Physical gameplay and vendor firmware still need testing |
| ABI / TV | ARM64 and x86_64; experimental ARMv7 and x86 without Wasmtime. Android TV launcher entry, D-pad/Enter navigation, editable keypad profile with in-game focus navigation and retained utility buttons, plus portrait orientations; full analog gamepad backend remains unfinished |
| Unicode keyboard | Stock Android text editor and IME through Rust/JNI on the UI thread; system keyboard remains responsible for its own clipboard suggestions |
| Horizon clipboard actions | Newly connected to Android ClipboardManager for explicit text copy/paste; no background clipboard polling or file-URI reads |
| Sound and subtitles | AAudio mixer and downloaded sound assets; existing category volumes, subtitles and accessibility settings remain available |
| Graphics / streaming | Client-resolution presets and numeric input scale the complete frame, including menus and HUD, from 25–100%, subject to minimum menu dimensions. Existing game graphics controls remain available; launcher selects real Vulkan draw paths |
| Sandboxed Horizon mods | 64-bit builds: Wasmtime `.hmod` runtime for the content part; 32-bit omits this runtime; existing capabilities and errors appear in the game mod menu. A unified `.hmod` may bundle content plus native Rust source — the content stays sandboxed, the native part does not. Official Horizon Mods catalog and direct HTTPS import; no Java-mod search or Java/Mixin execution |
| Native mods (.hmod / legacy .hnmod) | A unified `.hmod` carries content plus native source (detected by `horizon-native.json`); legacy `.hnmod` is native-only. Storage is `<game>/horizon-native-mods/<id>.hmod`/`.hnmod`, with the content part mirrored to `horizon-mods/<id>.hmod`; "Play without native mods" stops the native build but keeps that content. Native code runs UNSANDBOXED with full device access and is compiled on a GitHub-hosted runner through the fork's build service (Compile button in Mods → Native mods); the APK itself never compiles Rust. The Java loader/trampoline is unchanged. Device testing of the full import → compile → install → restart cycle is still outstanding (only the load chain was checked with a prebuilt no-op mod). Pasted HTTPS native imports get no registry hash/signature check unless the URL matches a known registry file; see [android-native-mods.md](android-native-mods.md) |
| Resource packs | Checksum-verified resource-pack search/install; modpack browsing, importing, selection and automatic launch hooks are removed on Android |
| APK distribution | Dedicated `--public` build: 32 generated tables, original resources downloaded from official sources on the phone, no automatic agent socket; no player PC preparation |
| Single player | Default integrated server and optional in-frame path. Editor pauses unpublished single player through the engine pause decision |
| Servers | Existing protocol 777 client. Manual matching-version server address supported; Android device-code sign-in and session handoff implemented; temporary Switch dev ID with Microsoft Live device-code flow, browser Custom Tab, code copy and persistent pending login; initial code request accepted, full account login unverified |
| Play with Friends | Shared core exists, but relay/account/clipboard/background behavior needs an Android end-to-end pass before advertising parity |
| Saves and backups | Engine save logic works; by default the saves live in app storage and Files → Horizon Android exposes them through the documents provider. Uninstalling deletes internal data; with the game files location moved to shared storage the Horizon-Android folder stays on the device |
| Lifecycle | Touch/key cancellation, vibration stop and surface release/recreation. Leaving the game returns to the native launcher; background process termination still needs broader save/recovery testing |
| Launcher startup UX | The Compose launcher shows an animated splash while the first native snapshot loads and transitions into the launcher when it is ready. If the bridge does not answer, a failure panel with a Retry button replaces the spinner instead of waiting forever; Android's reduced-animation setting is respected. A previous-run Kotlin crash surfaces as a one-time notice, with reports available through the diagnostics ZIP |
| Launcher appearance | Light, dark and system themes; seven contrast-checked accents plus system colours; an image picked through Android Documents is copied and downscaled into private app storage, with default fallback when that copy is missing. Preferences persist in `android-appearance.json`, changes apply immediately, and reset restores the original look |
| Screenshot gallery | Play/Settings gallery discovers screenshots in every instance, shows sampled thumbnails in a responsive grid, and opens a pinch-zoom preview with filename, resolution, size and date. Newest/oldest/name sorting and instance grouping are available. Sharing uses a private read-only provider with a temporary URI grant, never a filesystem path; confirmed deletion also tolerates files already removed. The MediaStore copy in Pictures remains independent |
| Android file access | System-picker import for add-ons; by default, Horizon Android in system Files exposes mods, resource packs, shaders, worlds, the four allowlisted configuration files and reports while game files stay internal. With Settings > Storage > Game files location (a two-option chooser, internal storage recommended) the player-facing files (worlds, mods, packs, shaders, options, servers.dat, screenshots, instances and the shareable reports) move into /storage/emulated/0/Horizon-Android after the user grants the storage access Android shows; the move and the reverse are offered there too, a one-time prompt on first launch asks to move, and everything stays exactly as it was if the grant is refused. Logs, accounts, downloaded Minecraft files and raw diagnostics stay private. F2 gallery export uses MediaStore; Android 8.1–9 requests storage access for that explicit action. Worlds and configuration can be copied, moved, replaced or deleted in Files while the game is closed; fixed root folders themselves and Reports stay read-only, and dedicated ZIP-world import/export remains separate |
| Physical device tuning | Thermal/frame-pacing and GPU-driver comparisons need measurements on the target phone; an emulator is not evidence of phone performance |
| Desktop updates / telemetry services | Desktop deployment/auto-update infrastructure is not an Android updater; fork exports keep original workflows inactive |

Priorities after this change: world import/export, Minecraft Services approval and production account validation,
hardware gamepads, then measured lifecycle and thermal behavior. Preserve
the current engine performance baseline while adding these platform bridges.
